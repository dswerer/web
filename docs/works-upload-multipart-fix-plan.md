# 学生作品附件提交修复计划

## 问题与验收

学生从课后任务进入作品提交页时，界面说明允许“文字或附件至少填写一种”，但选择附件后提交会报错。验收标准如下：

1. 仅提交符合格式的附件，接口返回成功并保存附件信息；
2. 仅提交文字，接口返回成功；
3. 文字和附件均为空，接口返回 400；
4. 历史 `require_upload=1` 配置的任务也接受仅文字提交；
5. 前端 lint、build 及后端全部自动化测试通过。

## 设计边界与决策

- 作品提交统一采用文字与附件二选一规则；历史 `tasks.require_upload` 配置不再作为服务端强制拦截条件。
- 不改数据库结构、作品权限或上传格式白名单；上传文件继续走鉴权 API 和现有魔数校验。
- 根因处理包括两处：浏览器必须自行生成 multipart boundary；Multer v2 的 `fileFilter` 不提供 `file.stream`，文件签名校验必须在落盘后执行。

## 实施顺序

| 批次 | 文件 | 改动 | 预设提交 |
| --- | --- | --- | --- |
| 1 | `frontend/src/api/index.js`、`backend/middleware/upload.js`、`backend/routes/{works,courses}.js` | 清除 `FormData` 请求的显式 `Content-Type`；将与 Multer v2 不兼容的流式魔数校验改为落盘后校验，保留所有上传入口的签名校验 | `fix(works): 修复学生附件作品提交` |
| 2 | `backend/test/workPolicy.test.js` | 覆盖仅附件、仅文字、空内容、历史附件要求配置和伪造文件的回归场景 | `test(backend): 补充作品提交回归测试` |
| 3 | `README.md` | 记录提交规则、附件上限和验证覆盖 | `docs(readme): 补充作品提交说明` |

## 回归清单

- 学生从课后任务入口仅选择 PDF 附件并提交；
- 学生仅填写文字并提交非强制附件任务；
- 学生不填写任何内容时得到明确提示；
- 历史强制附件配置不阻止纯文字提交；
- 不支持格式、伪造文件和超大文件仍由既有上传中间件拒绝。
